## What's inside

- `data/` folder from a live Cosmos Hub (`cosmoshub-4`) `gaiad` full node running on **GoLevelDB** with pruning (`custom` / `keep-recent=100` / `interval=19`).

**Download:** [snapshots.unitynodes.com/cosmos-mainnet/latest.tar.lz4](https://snapshots.unitynodes.com/cosmos-mainnet/latest.tar.lz4) - refreshed every 4 hours.

Full archive listing: [snapshots.unitynodes.com/cosmos-mainnet/](https://snapshots.unitynodes.com/cosmos-mainnet/)

<Warning>
  This is a **pruned** snapshot. It is meant for validators, full nodes and RPC endpoints that
  only need recent state. It cannot serve historical queries - for that you need an archive node.
</Warning>

## Restore

Pick the variant you need - each tab has its own copy button.

| Variant | Taken at | Use it when |
|---|---|---|
| **Latest** | every 4 hours | normal bootstrap of a node |
| **Pre-upgrade** | `H-1`, the last block before a scheduled upgrade height | you want to cross the upgrade yourself, on the old binary, exactly as the network does |
| **Post-upgrade** | shortly after the upgrade height, on the new binary | you are joining after an upgrade and want migrated state with no upgrade handling at all |

<CodeGroup>

```bash Latest
sudo systemctl stop gaiad

cp $HOME/.gaia/data/priv_validator_state.json $HOME/.gaia/priv_validator_state.json.backup

rm -rf $HOME/.gaia/data
curl -L https://snapshots.unitynodes.com/cosmos-mainnet/latest.tar.lz4 | lz4 -dc - | tar -xf - -C $HOME/.gaia

mv $HOME/.gaia/priv_validator_state.json.backup $HOME/.gaia/data/priv_validator_state.json

sudo systemctl restart gaiad && sudo journalctl -u gaiad -fo cat
```

```bash Pre-upgrade (H-1)
sudo systemctl stop gaiad

cp $HOME/.gaia/data/priv_validator_state.json $HOME/.gaia/priv_validator_state.json.backup

rm -rf $HOME/.gaia/data
curl -L https://snapshots.unitynodes.com/cosmos-mainnet/pre-upgrade.tar.lz4 | lz4 -dc - | tar -xf - -C $HOME/.gaia

mv $HOME/.gaia/priv_validator_state.json.backup $HOME/.gaia/data/priv_validator_state.json

# start on the OLD binary - the chain will halt at the upgrade height, then swap and restart
sudo systemctl restart gaiad && sudo journalctl -u gaiad -fo cat
```

```bash Post-upgrade
sudo systemctl stop gaiad

cp $HOME/.gaia/data/priv_validator_state.json $HOME/.gaia/priv_validator_state.json.backup

rm -rf $HOME/.gaia/data
curl -L https://snapshots.unitynodes.com/cosmos-mainnet/post-upgrade.tar.lz4 | lz4 -dc - | tar -xf - -C $HOME/.gaia

mv $HOME/.gaia/priv_validator_state.json.backup $HOME/.gaia/data/priv_validator_state.json

# start on the NEW binary for that upgrade
sudo systemctl restart gaiad && sudo journalctl -u gaiad -fo cat
```

</CodeGroup>

<Note>
  `pre-upgrade` and `post-upgrade` exist only around a scheduled Cosmos Hub upgrade. The
  [archive listing](https://snapshots.unitynodes.com/cosmos-mainnet/) shows which variants are
  currently published, and each one ships a `.txt` sidecar naming the upgrade it belongs to.
</Note>

<Warning>
  Do not skip the `priv_validator_state.json` backup step. That file records the last height and
  round your validator signed. Restoring somebody else's signing state - or an older copy of your
  own - is the classic way to double-sign and get slashed.
</Warning>

## FAQ

<AccordionGroup>
  <Accordion title="How often is the snapshot updated?">
    Every **4 hours**. The last 2 snapshots are kept online.
  </Accordion>
  <Accordion title="What db backend?">
    `goleveldb`.
  </Accordion>
  <Accordion title="Can I use this to bootstrap a validator?">
    Yes. The tarball contains only `data/`. There is no `config/` directory in it, so no
    `priv_validator_key.json`, no `node_key.json` and no keyring - your identity files are never
    overwritten by a restore.
  </Accordion>
  <Accordion title="How is the snapshot kept small?">
    The producing node is pruned (`custom` / `keep-recent=100` / `interval=19`), so it retains
    only recent state rather than full chain history.
  </Accordion>
  <Accordion title="Is the node stopped while the snapshot is taken?">
    Yes, briefly. The archive is a cold tar taken with `gaiad` stopped, so the database is never
    copied mid-write.
  </Accordion>
</AccordionGroup>
